Submit a simulation record (beta)

Simulation records are JSON that validates against SMASH-SIM v1.0.0. Authors can submit a record directly; automatic records show the evidence snippet behind every value.

Experimental record Simulation record

Before you submit

  1. Give the source first: DOI or URL, licence, version and retrieval date. A simulation record is about one system under one model and one protocol.
  2. Say what the units are. If the model reports reduced units, set model.unit_system to reduced (or reduced_with_stated_conversion) and put any conversion the paper states in model.unit_conversions. Never convert a reduced value to a physical unit yourself.
  3. Describe the pulling geometry with the same vocabulary as the experimental records (force_application_geometry), and name the anchors (residues, nucleotides, or ends) so the record can be matched.
  4. Every value needs its evidence: the field, the method, a snippet, and a confidence.
  5. Identifiers (UniProt, PDB, Rfam, GenBank) must resolve; a code that cannot be resolved is left out rather than guessed.

Minimal valid record

Only the required blocks are shown. Validate it with hub/sim/schema.py before sending it.

{
  "record_id": "SIM-000123",
  "schema_version": "1.0.0",
  "category": "simulation",
  "source": {"kind": "publication", "doi": "10.0000/example", "retrieved": "2026-10-11"},
  "system": {"molecule_type": "protein", "name": "Titin I27 domain"},
  "model": {"family": "Go_CA", "family_group": "protein", "unit_system": "reduced_with_stated_conversion"},
  "protocol": {"mode": "constant_velocity"},
  "data_availability": {"status": "public_repository"}
}
