SMASH-SIM v1.0.0 (beta)

One record describes one simulated system, under one model and one pulling protocol, from one source. The schema reuses the published SMFS definitions and adds the parts a simulation needs.

The record, block by block

BlockWhat it records
record_id, schema_version, category SIM-######, 1.0.0, and the fixed label simulation.
source publication, dataset, database or smash_sim_generated, with DOI/URL, licence, version, retrieval date, and the SHA-256 of anything ingested.
system Molecule type (protein, DNA, RNA, DNA/RNA–protein, complex), entities with resolver-verified identifiers, the construct (residue or nucleotide range), structure_source (PDB, AlphaFold, predicted secondary structure, designed) and the structure ids.
model Family (Go Cα, heavy-atom Go, SOP, AWSEM, Martini, all-atom explicit/implicit, oxDNA, oxRNA, TIS, HiRE-RNA, thermodynamic nearest-neighbour, other), force field or parameter set, solvent, software and version, the unit_system, and any stated conversions from reduced units.
protocol Mode (constant velocity, constant force, force ramp, boxed MD, equilibrium under force), pulling speed (original unit, plus m/s when physical), spring constant, temperature, number of trajectories, simulated time, and the pulling geometry in the same vocabulary as the experimental records so the two can be matched.
results The published SMFS result structure — unfolding force, ΔLc, x‡, k0, ΔG‡, number of intermediates, toughness, work, loading rate — each with a unit_system and an evidence entry.
links.experimental_matches[] SMASH-BIO and MechanoProDB records for the same molecule, each with a match_level: same_construct_same_geometry, same_molecule_different_geometry or homolog.
data_availability Whether trajectories, force–extension curves, input files (topologies, parameters) and analysis scripts are shared, with formats and locations.
fair_completeness Fraction of the category's own fields populated per section (publication, system, model, protocol, results, data) and overall.

Validation

Every record is validated against the schema before it is published. Records that fail validation are excluded from the downloads and listed in the run report. Shared definitions are referenced from the published SMFS 3.1.0 schemas (../schema/smash-smfs-record.schema.json, ../schema/smash-smfs-results.schema.json); nothing in them is modified.

Downloads

Only data whose licence allows redistribution is in the downloads. Where a dataset's licence does not permit it, the record indexes the metadata and links to the source instead.

  • smash-sim-records.jsonl.gz — every published simulation record, one JSON object per line
  • smash-sim-summary.csv — one row per record: source, system, model, protocol, units, data status, match levels
  • smash-sim-matches.csv — every simulation ↔ experiment link with its match level and the forces on both sides
